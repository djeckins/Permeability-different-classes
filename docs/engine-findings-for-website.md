# Что из платформы реально работает сегодня (проверено запуском)

Движок проницаемости — **одна позиция в каталоге**, а не центр главной. Но это
единственная часть платформы, которую я смог запустить и проверить, поэтому она
задаёт планку достоверности для всего каталога: если публиковать список
возможностей в стиле playmolecule, то каждая строка должна быть такой же
проверяемой, как эти.

## Проверено: работает end-to-end на CPU за секунды

Запущено на панели из 8 молекул (парацетамол, гидрохинон, галловая кислота,
глицерин, ибупрофен, ресвератрол, ацетилхолин, цетримониум).

| Слой | Что считает | Провенанс |
|---|---|---|
| Дескрипторы | MW, TPSA, HBD, HBA, RotB, HAC, formal charge, cLogP | RDKit |
| Ионизация | pKa (GNN), класс ионизации, доля неионизованной формы при pH 5.5, LogD | pKaLearn — Genzling, Luo, Weiser, Moitessier (McGill) |
| Мембранный транспорт | logP_BLM, logP_PAMPA, logP_Caco2, logP_plasma, logP_BBB | PerMM / pypermm, физическая implicit-membrane модель |
| Структурные алерты | PAINS, BRENK | RDKit каталоги |
| Скоринг кожи | 9 взвешенных критериев → 0–100 → PASS / BORDERLINE / FAIL | собственная модель |

Пример реального выхода (скрин по коже):


Физика ведёт себя корректно: глицерин и галловая кислота получают logP_BLM около

Это защитимые числа.

## Две проблемы, которые надо закрыть ДО публикации каталога

### 1. Четыре из пяти «маршрутов применения» — один и тот же файл

`hair_care.py`, `oral_care.py`, `supplement_oral.py`, `supplement_transbuccal.py`
различаются **нулём строк** после нормализации названия маршрута (все по 407 строк,
diff пустой). Выходы на тестовой панели совпадают до десятых:

```
molecule       Skin    Hair    Oral    Suppl.oral  Suppl.transbuccal
Resveratrol    100.0   96.5    96.5    96.5        96.5
Gallic acid     73.5   77.5    77.5    77.5        77.5
Glycerin        71.5   79.5    79.5    79.5        79.5
```

Отдельная логика есть только у `skin_care.py` (465 строк, 9-критериальная модель).
Значит, сегодня это **одна общая модель + одна специализированная под кожу**, а не
пять независимых. Заявлять на главной «пять маршрутов» — это ровно тот тип
переобещания, от которого playmolecule старательно уходит («Scientific decisions
remain yours», «flagged where the geometry is strained»). Либо
дифференцировать четыре модуля, либо в каталоге писать честно: одна валидированная
модель кожи + общий физико-химический скрин.

### 2. Постоянно заряженные катионы проходят скрин кожи

`_classify_formal_charge` (skin_care.py:102) даёт «acceptable» (5 из 10 баллов)
любому заряду ±1, не различая **титруемый** заряд (молекула бывает нейтральной при
каком-то pH) и **постоянный** (четвертичный аммоний — нейтральной не бывает никогда).

```
Acetylcholine (quat, +1)   formal_charge=+1  expected_net_charge=0.0  → 85.0 PASS
Cetrimonium   (quat, +1)   formal_charge=+1  expected_net_charge=0.0  → 70.0 BORDERLINE
```

Четвертичные аммонийные соединения — это весь класс кондиционирующих агентов
(cetrimonium, behentrimonium, benzalkonium), коммерчески один из самых важных в
косметике. Сейчас они проходят как пассивно проникающие через роговой слой, чего
не происходит. Причина: при `ionization_class = non_ionizable` код обнуляет
`expected_net_charge`, теряя перманентный заряд.

**Вывод для главной:** каталог возможностей публиковать можно и нужно, но каждая
строка должна соответствовать тому, что реально считается. Эти два пункта —
предусловие, а не отдельная задача.
